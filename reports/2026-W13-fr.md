## I. Pattern de migration unifié

Toutes les conversions de noyaux suivent un schéma identique :

**Avant (CPU-only)**
```cpp
void SomeKernel(Domain& domain, ...) {
    Kokkos::parallel_for("label", N, [&](Index_t i) {
        // accès direct à domain.m_xxx.m_yyy(i)
        // appel de domain.someMethod() — fonction hôte
    });
}
```

**Après (compatible GPU)**
```cpp
void SomeKernel(Domain& domain, ...) {
    auto x_v = domain.m_nodes.m_x;
    auto y_v = domain.m_nodes.m_y;
    // ...
    Kokkos::parallel_for("label", N, KOKKOS_LAMBDA(Index_t i) {
        Real_t xi = x_v(i);
    });
}
```

La capture `[=]` d'un `Kokkos::View` ne copie que ses métadonnées (pointeur + extent). Sur GPU, le noyau accède directement à la mémoire device ; sur OpenMP, à la mémoire hôte.

## II. Modifications par module

### 2.1 `lulesh-timestep.cc`

Extraction de 3 Views (`vdov_v`, `ss_v`, `arealg_v`), `KOKKOS_LAMBDA`, `std::sqrt/fabs` → `Kokkos::sqrt/fabs`. Les réductions `Kokkos::Min<Real_t>` à double réducteur (W11) sont conservées.

### 2.2 `lulesh-viscosity.cc`

`CalcMonotonicQGradientsForElems` : extraction de 14 Views, accès à la connectivité via décalage de pointeur brut (`nodelist_v.data() + 8*i`). `CalcMonotonicQForElems` : `fprintf(stderr, ...)` → `Kokkos::abort` (illégal côté device).

### 2.3 `lulesh-kinematics.cc`

`CalcElemVelocityGradient` : `static inline` → `KOKKOS_INLINE_FUNCTION static`. `CalcLagrangeElements` : `CollectDomainNodesToElemNodes(domain, ...)` (reçoit `Domain&`, inaccessible sur GPU) → boucle inline sur 8 nœuds. `exit(VolumeError)` → `Kokkos::abort`.

### 2.4 `lulesh-nodal.cc`

4 `Kokkos::parallel_for` : extraction des Views, `KOKKOS_LAMBDA`, `std::fabs` → `Kokkos::fabs`.

### 2.5 `lulesh-eos.cc`

`CalcEnergyForElems` : signature de 14 pointeurs bruts → 14 `Kokkos::View<Real_t*>`. `EvalEOSForElems` : encapsulation zéro-copie de `regElemList` en View non gérée (pour CUDA : remplacer par `deep_copy`). `ApplyMaterialPropertiesForElems` : `exit(VolumeError)` → `Kokkos::abort`.

### 2.6 `lulesh-stress.cc`

`SumElemStressesToNodeForces` et `CalcElemFBHourglassForce` : `static inline` → `KOKKOS_INLINE_FUNCTION static`. `IntegrateStressForElems` : scatter buffers `std::aligned_alloc` → `Kokkos::View<Real_t*>` ; suppression de la branche `numthreads > 1` (écriture directe sur GPU = race condition) ; chemin scatter/gather systématique.

## III. Erreur de liaison et correction

Après conversion de tous les fichiers, première construction :

```
Undefined symbols for architecture arm64:
  "CalcElemVolume(double const*, ...)", referenced from:
      CalcLagrangeElements(...) in lulesh-kinematics.cc.o
  "CalcElemNodeNormals(...)", referenced from:
      IntegrateStressForElems(...) in lulesh-stress.cc.o
ld: symbol(s) not found for architecture arm64
```

**Cause racine** : `KOKKOS_INLINE_FUNCTION` contient `inline`. La règle ODR exige que la définition d'une fonction `inline` soit visible dans chaque unité de traduction qui l'appelle. Les définitions géométriques étaient dans `src/lulesh-geometry.cc`, inaccessibles aux appelants.

**Correction** : déplacement de toutes les définitions `KOKKOS_INLINE_FUNCTION` dans `include/lulesh-geometry.h`. `CollectDomainNodesToElemNodes` (fonction hôte) reste dans le `.cc`.

## V. Décisions techniques

### 1. Définitions `KOKKOS_INLINE_FUNCTION` dans les en-têtes

Conséquence conjointe de la règle `inline` du C++ et des exigences Kokkos : toute fonction appelée depuis un `KOKKOS_LAMBDA` doit être définie dans un en-tête.

### 2. Remplacement inline de `CollectDomainNodesToElemNodes`

Fonction hôte recevant `Domain&` : remplacement par boucle inline sur 8 nœuds à chaque point d'appel, modification minimale, aucune perte sémantique.

### 3. Suppression de la branche `numthreads > 1`

Optimisation CPU-only : en mono-thread, évite le scatter. Sur GPU, l'écriture directe sans scatter provoquerait des races. Le chemin scatter/gather est la seule approche correcte.

### 4. View non gérée pour `regElemList`

Zéro-copie pour OpenMP/HostSpace. Pour CUDA : View gérée + `deep_copy` requis (commentaire en place dans le code).

## VI. Débogage CUDA complet

### 6.1 Premier cycle : `--expt-extended-lambda` manquant

**Symptôme** :

```
FunctorType = lambda [](Index_t)->void
calling a constexpr __host__ function from a __device__ function is not allowed.
```

`KOKKOS_LAMBDA` → `[=] __host__ __device__` nécessite `--expt-extended-lambda` transmis par Kokkos uniquement si `Kokkos_ENABLE_CUDA_LAMBDA=ON`. Installation Linux sans cette option → lambda `__host__` uniquement.

**Correction initiale** :

```cmake
target_compile_options(lulesh PRIVATE
    $<$<COMPILE_LANGUAGE:CUDA>:--expt-extended-lambda>
)
```

### 6.2 Deuxième cycle : macro `_OPENMP` non définie

**Symptôme** : `#error "You enabled Kokkos OpenMP support without enabling OpenMP in the compiler!"`

**Cause** : nvcc ne transmet pas `-fopenmp` au compilateur hôte lors de la compilation de fichiers à langage CUDA. `_OPENMP` reste indéfini.

**Correction** :

```cmake
$<$<COMPILE_LANGUAGE:CUDA>:-Xcompiler=-fopenmp>
```

### 6.3 Troisième cycle : préfixe `_INTERNAL_` sur les noms de lambda

**Symptôme** :

```
template argument 1 is invalid
FunctorType = lambda []( ::, ...)->void
```

**Cause racine** : la propriété `LANGUAGE CUDA` sur les fichiers `.cc` fait que CMake les route vers `CMAKE_CUDA_COMPILER` (nvcc direct), et non vers `CMAKE_CXX_COMPILER` (nvcc_wrapper). nvcc appelé directement sur un `.cc` attribue aux lambdas un préfixe `_INTERNAL_` que son propre outil cudafe1 ne peut pas démêler.

**Distinction clé** :

| Chemin | Nom du lambda | Raison |
|--------|---------------|--------|
| nvcc_wrapper (chemin CXX) | Nom externe normal | nvcc_wrapper renomme `.cc` → `.cu` en interne |
| nvcc direct (chemin CUDA) | Préfixe `_INTERNAL_` | nvcc traite les extensions non-`.cu` avec des noms restreints |

**Correction** : suppression de `set_source_files_properties(... LANGUAGE CUDA)` ; toutes les sources restent en CXX, traitées par nvcc_wrapper. `--expt-extended-lambda` déplacé vers `COMPILE_LANGUAGE:CXX`. `-Xcompiler=-fopenmp` supprimé (`OpenMP::OpenMP_CXX` le transmet via CXX).

`CMakeLists.txt` — détection nvcc_wrapper/g++ :

```cmake
if(CMAKE_CXX_COMPILER MATCHES "nvcc_wrapper")
    # Path A : nvcc_wrapper — pas de LANGUAGE CUDA, --expt-extended-lambda via CXX
    target_compile_options(lulesh PRIVATE
        $<$<COMPILE_LANGUAGE:CXX>:--expt-extended-lambda>
    )
else()
    # Path B : g++ + kokkos_launch_compiler (avertissement)
    message(WARNING "Utiliser nvcc_wrapper est recommandé")
endif()
```

### 6.4 Cause racine persistante : `Kokkos_ENABLE_CUDA_LAMBDA=ON` absent

Après toutes les corrections de `CMakeLists.txt`, l'erreur `FunctorType = lambda [](Index_t)->void` persiste.

**Cause racine** : l'expansion de `KOKKOS_LAMBDA` est figée à la **compilation de Kokkos** :

- Kokkos compilé avec `Kokkos_ENABLE_CUDA_LAMBDA=ON` → `KOKKOS_LAMBDA` = `[=] __host__ __device__` ✓
- Kokkos compilé sans → `KOKKOS_LAMBDA` = `[=]` (hôte uniquement) ✗

`--expt-extended-lambda` est un prérequis nécessaire mais pas suffisant : il autorise nvcc à accepter les lambdas `__device__`, mais ne peut pas ajouter `__device__` à un lambda qui ne l'a jamais eu.

L'installation Kokkos de la machine Linux n'avait pas activé cette option : c'est la cause racine de toutes les erreurs CUDA.

**Solution** : recompiler Kokkos sur la machine Linux avec `Kokkos_ENABLE_CUDA_LAMBDA=ON` :

```bash
cmake -S /path/to/kokkos -B /tmp/kokkos-build \
    -DCMAKE_INSTALL_PREFIX=/path/to/kokkos/install \
    -DKokkos_ENABLE_CUDA=ON \
    -DKokkos_ENABLE_CUDA_LAMBDA=ON \    # ← correction clé
    -DKokkos_ENABLE_OPENMP=ON \
    -DKokkos_ARCH_AMPERE80=ON \
    -DCMAKE_CXX_COMPILER=/path/to/kokkos/bin/nvcc_wrapper \
    -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/kokkos-build -j$(nproc) && cmake --install /tmp/kokkos-build
```

Aucune modification des sources LULESH ni du `CMakeLists.txt` n'est nécessaire.

## VII. Script `build-cuda.sh`

L'ensemble du flux (reconstruction Kokkos + compilation LULESH + vérification) est encapsulé dans un script paramétrable :

```bash
./scripts/build-cuda.sh                              # A100 (défaut)
./scripts/build-cuda.sh --arch VOLTA70 --cuda-arch 70  # V100
./scripts/build-cuda.sh --skip-kokkos               # LULESH seulement
```

Étapes automatisées : configuration Kokkos (avec CUDA_LAMBDA=ON) → compilation + installation → configuration LULESH → compilation → vérification `-s 10 -i 50`.

## VIII. Nettoyage du code mort

Après la migration, `src/lulesh-geometry.cc` ne contenait plus que la définition de `CollectDomainNodesToElemNodes`. Tous les sites d'appel avaient été remplacés par des boucles inline ; la fonction n'était plus jamais appelée.

| Action | Détail |
|--------|--------|
| Suppression de `src/lulesh-geometry.cc` | Seule la définition d'une fonction jamais appelée |
| Suppression de la déclaration dans `include/lulesh-geometry.h` | Déclaration correspondante orpheline |
| Mise à jour de `CMakeLists.txt` | Retrait de `src/lulesh-geometry.cc` de la liste SOURCES |
| Correction du chemin par défaut de `scripts/run-openmp.sh` | `build/release` → `build`, cohérent avec cmake manuel |

Validation après nettoyage : `-s 10 -i 50` → `8.104796e+04` ✓. Aucune régression.
