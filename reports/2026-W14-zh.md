# 周报 2026-W14 | LULESH 2.0 GPU 优化 P1：消除全部每步 cudaMalloc/cudaFree

**周期**：2026-03-30 ~ 2026-04-05
**项目**：LULESH 2.0 高性能计算代理应用（Kokkos 5 / GPU 迁移，`gpu-port` 分支）
**平台**：macOS Apple Silicon（OpenMP 后端本地验证）；目标平台：Linux + RTX 4070 Laptop GPU（CUDA 后端）
**正确性基准**：`OMP_PROC_BIND=close ./build/lulesh2.0 -s 10 -i 50` → `Final Origin Energy = 8.104796e+04`

---

## 本周工作概览

本周完成 **P1 优化**：通过在 `Domain` 构造函数中一次性预分配全部瞬态 `Kokkos::View`，将原先每个时间步约 28 次 `cudaMalloc + cudaFree` 调用（含每次 `EvalEOSForElems` 调用时的 `regElemList` 动态分配）归零。上周 GPU 性能剖析（Nsight Systems）已证实 `cudaMalloc/cudaFree` 占总 CUDA API 时间的 70–80%，是小规模问题（`s≤90`）GPU 性能不及 CPU 的首要根因。

---

## 一、问题根因与分析

### 1.1 剖析数据

Nsight Systems 对 `-s 30 -i 10` 的统计：

| API 调用 | 总耗时占比 | 调用次数 |
|----------|-----------|---------|
| `cudaMalloc` + `cudaFree` | ~75% | ~337 次 |
| 所有 CUDA 内核执行 | ~0.7% | ~350 次 |

结论：内存分配开销远超实际计算，GPU 的 90%+ 时间花费在内存管理而非数值计算上。

### 1.2 每步分配源头（完整清单）

迁移前代码在每个时间步内动态分配以下 `Kokkos::View`：

| 来源 | View 名称 | 大小 | 次数/步 |
|------|-----------|------|--------|
| `EvalEOSForElems`（每区域） | `regElemList` | `numElemReg` | 11（默认 11 区域）|
| `IntegrateStressForElems` | `fx/fy/fz_elem` | `numElem × 8` | 3 |
| `CalcHourglassControlForElems` | `hg_fx/fy/fz_elem` | `numElem × 8` | 3 |
| `CalcVolumeForceForElems` | `determ` | `numElem` | 1 |
| `LagrangeElements` | `vnew` | `numElem` | 1 |
| `AllocateGradients`（viscosity） | `delx/delv_xi/eta/zeta` | `numElem / allElem` | 6 |
| `AllocateStrains`（kinematics） | `dxx/dyy/dzz` | `numElem` | 3 |
| **合计** | | | **~28/步** |

## 二、P1 优化实现

### 2.1 设计思路

将上述全部瞬态 `View` 提升为 `Domain` 的成员变量，在构造函数中一次分配，后续每步复用，彻底消除运行期 `cudaMalloc/cudaFree`。

### 2.2 `include/lulesh.h` 修改

**① `ElemConnectivity` 新增设备端区域索引列表**

```cpp
struct ElemConnectivity {
    // ... 原有成员 ...
    std::vector<std::vector<Index_t>> m_regElemlist;    // 宿主端（保留）
    std::vector<Kokkos::View<Index_t*>> m_regElemlist_d; // ← 新增：设备端副本（P1）
} m_conn;
```

**② `ElemState` 新增 `ScratchViews` 结构体**

```cpp
struct ElemState {
    // ... 原有成员 ...

    struct ScratchViews {
        Kokkos::View<Real_t*> m_vnew;                            // 相对体积（numElem）
        Kokkos::View<Real_t*> m_determ;                          // Jacobi 行列式（numElem）
        Kokkos::View<Real_t*> m_fx_elem, m_fy_elem, m_fz_elem;  // 应力散射缓冲（numElem×8）
        Kokkos::View<Real_t*> m_hg_fx,   m_hg_fy,   m_hg_fz;   // 沙漏散射缓冲（numElem×8）
        void reserve(Index_t numElem) { /* 一次性分配全部 */ }
    } m_scratch;

    struct EosTemps { /* 已有，保留 */ } m_eosTemps;
} m_elems;
```

**③ 梯度/应变 View 改为构造时分配**

```cpp
// 公有方法改为无操作（调用点无需修改）
void AllocateGradients(Int_t, Int_t) {}   // P1：已在构造函数中分配
void DeallocateGradients() {}
void AllocateStrains(Int_t) {}
void DeallocateStrains() {}
```

**④ 新增访问器与私有方法**

```cpp
// 公有访问器
Kokkos::View<Index_t*>& regElemlistDevice(Int_t r) {
    return m_conn.m_regElemlist_d[r];
}

// 私有（仅构造函数调用）
void AllocateScratch(Int_t numElem, Int_t allElem);
```

### 2.3 `src/lulesh-init.cc` 修改

在 `CreateRegionIndexSets` 之后，构造函数中添加：

```cpp
// P1-A：将 11 个区域索引表上传至设备，全程只做一次
m_conn.m_regElemlist_d.resize(numReg());
for (Int_t r = 0; r < numReg(); ++r) {
    Kokkos::View<const Index_t*, Kokkos::HostSpace>
        h(m_conn.m_regElemlist[r].data(), regElemSize(r));
    m_conn.m_regElemlist_d[r] =
        Kokkos::View<Index_t*>("regElemList_r", regElemSize(r));
    Kokkos::deep_copy(m_conn.m_regElemlist_d[r], h);
}

// P1-B：预分配全部每步临时 View
Int_t allElem = numElem()
              + 2*sizeX()*sizeY()
              + 2*sizeX()*sizeZ()
              + 2*sizeY()*sizeZ();
AllocateScratch(numElem(), allElem);
```

### 2.4 各计算模块修改

| 文件 | 原代码 | 修改后 |
|------|--------|--------|
| `lulesh-eos.cc` | `Kokkos::View<Index_t*> regElemList("...", n); Kokkos::deep_copy(...)` | `Kokkos::View<Index_t*> regElemList = domain.regElemlistDevice(r)` |
| `lulesh-integration.cc` | `Kokkos::View<Real_t*> vnew("vnew", numElem)` | `auto& vnew = domain.m_elems.m_scratch.m_vnew` |
| `lulesh-stress.cc`（IntegrateStress） | `Kokkos::View<Real_t*> fx_elem("fx_elem", n8)` ×3 | `auto& fx_elem = domain.m_elems.m_scratch.m_fx_elem` 等 |
| `lulesh-stress.cc`（CalcHourglass） | `Kokkos::View<Real_t*> fx_elem("hg_fx_elem", n8)` ×3 | `auto& fx_elem = domain.m_elems.m_scratch.m_hg_fx` 等 |
| `lulesh-stress.cc`（CalcVolumeForce） | `Kokkos::View<Real_t*> determ("determ", numElem)` | `auto& determ = domain.m_elems.m_scratch.m_determ` |
| `lulesh-viscosity.cc` | `domain.AllocateGradients(...)` / `DeallocateGradients()` | 无操作（自动省略） |
| `lulesh-kinematics.cc` | `domain.AllocateStrains(...)` / `DeallocateStrains()` | 无操作（自动省略） |

## 四、技术要点

### 4.1 `Kokkos::View` 复制语义

`auto& vnew = domain.m_elems.m_scratch.m_vnew` 中 `auto&` 是引用，不额外分配内存。传入函数时按值传递 `Kokkos::View`，复制的是元数据（指针 + extent），底层设备内存仍共享——这与原先按值传递局部 View 的语义完全一致。

### 4.2 区域循环串行安全性

11 个区域的 EOS 循环是串行执行的（`for (Int_t r = 0; r < numReg(); r++)`），`m_scratch` 中的临时 View 每次被单个区域独占使用，不存在数据竞争。EOS Temps 已有同样的设计（W12 就已如此）。

### 4.3 `allElem` 包含幽灵单元

`AllocateGradients` 的 `allElem` 参数 = `numElem + 6×面幽灵`，用于速度梯度 View（`delv_xi/eta/zeta`）的跨面查询。单域（无 MPI）时幽灵单元不被写入，但分配必须覆盖此范围以避免越界。
